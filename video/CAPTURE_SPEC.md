# Ripple deterministic capture specification

Status: PREPRODUCTION. Do not execute final capture until VIDEO_FREEZE_PACKET is complete.

## Objective

Capture reproducible, judge-credible footage of the real VIDEO-READY Ripple build. The capture must be repeatable from a known initial state and tied to one source revision.

## Capture engine

Preferred: Playwright + Chromium.

Why:
- deterministic viewport and timing
- scripted interaction path
- reproducible reset
- direct video capture
- no dependency on a human moving a mouse
- easy source-SHA annotation in capture metadata

## Required outputs

Keep raw capture separate from edited deliverables.

Suggested structure after freeze:

video/captures/<VIDEO_SHA>/
  capture-metadata.json
  golden-flow-full.webm
  opening-change.webm
  approval.webm
  execution-receipts.webm
  replay.webm
  platform-proof/

Do not commit large raw binaries if they make the repo impractical; GitHub Actions artifacts or another free durable location may be used. Preserve metadata and hashes in-repo.

## Deterministic environment

At capture time pin:
- source SHA
- live deployment identity
- browser version where possible
- viewport: 1920x1080 preferred
- device scale factor
- locale/language
- reduced-motion setting if relevant
- seed/reset procedure
- authentication/session state if required, without storing credentials in repo or logs

## Reset contract

The capture script must be able to establish the same initial state before every golden-flow take.

Reset must verify:
- no stale approval
- no stale receipts presented as new
- no previous external write that would make the take misleading
- expected starting plan/dependency state

If a real external provider action is reversible, reset it safely before the next take. If not safely reversible, design the capture to avoid repeated destructive actions.

## Golden capture checkpoints

The scripted run should emit timestamps/checkpoints for editing:

1. CHANGE_RECORDED
2. IMPACTS_VISIBLE
3. ECONOMIC_EXPOSURE_VISIBLE
4. REPAIR_PLAN_VISIBLE
5. EXACT_APPROVAL_VISIBLE
6. EXECUTION_STARTED
7. RECEIPTS_VISIBLE
8. REPLAY_STARTED
9. REPLAY_DEDUP_PROOF_VISIBLE

The editor should cut from checkpoint metadata where possible instead of guessing timing by eye.

## Proof integrity

A capture is invalid if:
- source revision cannot be tied to the deployed build
- pre-approval writes occur
- approval UI is skipped or hidden
- receipts are staged rather than generated by the run being shown
- replay proof is inferred rather than observable
- on-screen numbers differ from the verified output
- sensitive credentials/session data are visible

## Capture metadata

Recommended fields:

```json
{
  "source_sha": "...",
  "deployment_revision": "...",
  "captured_at": "ISO-8601",
  "live_url": "...",
  "scenario_id": "golden-flight-repair",
  "expected_impacts": null,
  "expected_at_risk": null,
  "expected_repair_cost": null,
  "expected_preserved": null,
  "expected_receipts": null,
  "expected_duplicate_writes_on_replay": 0,
  "raw_video_sha256": "..."
}
```

Populate all nulls from the VIDEO FREEZE packet, never from old documentation.

## Recording strategy

Record a clean full-flow take first. Then record surgical close-up takes only if needed for legibility.

Prefer editorial crops/punch-ins from a valid full take over recreating a state manually.

Do not use fake device chrome around the browser capture unless it materially improves comprehension and cannot be mistaken for official Alexa hardware proof.

## Audio capture

Capture product-generated audio separately or cleanly enough to isolate it in post.

If browser/system audio cannot be captured reliably in the automated environment, capture the visual proof deterministically and recreate only non-semantic SFX in post. Never fabricate an Alexa/product utterance and present it as recorded behavior.

## Security

Never record or expose:
- passwords
- MFA
- tokens
- cookies
- authorization codes
- account identifiers
- private console URLs
- secret-bearing logs

Any platform-proof shot must be pre-sanitized and framed to show only the evidence required for the claim.
